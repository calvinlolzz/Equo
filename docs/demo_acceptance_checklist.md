# Equo Demo 驗收與修正清單

日期：2026-06-30

## 驗收結論

目前 `references/index.html` 已可作為 MVP 前端流程 demo。它的定位是展示使用邏輯與資訊架構，不處理正式版才應由後端負責的登入、權限、資料保存、邀請碼驗證、結清版本與交易一致性。

## 建議展示路徑

1. 從群組首頁開始，說明主畫面只保留摘要與單一新增入口。
2. 建立一個新群組，確認空群組狀態。
3. 用邀請碼 `EQO7TWD` 加入範例群組。
4. 用右下角 `+` 新增支出，切換支出、收入、轉帳。
5. 打開支出記錄、分析、成員、近期活動。
6. 進入債務關係，執行結清。
7. 測封存、還原、刪除防護。
8. 打開 `Demo 路徑` 面板作為展示收尾。

## 已驗收流程

- 群組首頁：成員、總計、債務、支出記錄、近期活動能同步目前群組狀態。
- 建立群組：新群組會出現在群組清單並自動切換。
- 加入群組：`EQO7TWD` 可加入「台北週末」，錯誤邀請碼會提示失敗。
- 新增記錄：支出、收入、轉帳模式可切換，分配預覽會即時更新。
- 詳情面板：支出記錄、分析、債務、成員、活動、封存列表、Demo 路徑可開啟。
- 結清：確認後新增一筆轉帳記錄，債務顯示已結清。
- 安全操作：封存、還原、刪除都有二次確認與防護。
- 空狀態：新群組不會殘留舊資料。
- 響應式：桌面 `1280px` 與手機 `390px` 均無水平溢位。

## 留給正式版後端

- Google-only 登入與使用者身份。
- 邀請碼產生、使用次數、到期、權限檢查。
- 群組、成員、支出、付款人、分攤、結清紀錄的資料保存。
- 結清版本、歷史、重複送出防護。
- 封存、刪除的權限與後端安全確認。
- 多裝置同步與正式 API 錯誤處理。

## 進入 MVP 技術規劃前的修正清單

- 必修：將目前 demo 流程映射成正式資料模型與 API。
- 必修：定義 Google-only 登入後的群組與成員身份規則。
- 必修：定義支出、收入、轉帳與結清紀錄的資料結構差異。
- 必修：定義邀請碼的建立、加入、失效與重複加入行為。
- 可延後：圖片上傳、收據 OCR、離線同步、推播。
- 可延後：完整幣別匯率與多幣別結算。
